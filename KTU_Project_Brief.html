🎓 KTU University System

Activity Point Management System

A full-stack web application for managing, submitting, verifying, and tracking KTU student activity points as per the APJ Abdul Kalam Technological University 2024 guidelines.

University APJ Abdul Kalam Technological University
Type Web App (React + Vite)
Data Layer Browser localStorage (MVP)
User Roles Student · Faculty · Admin
01 — Overview

What is this system?

KTU mandates that all B.Tech students earn Activity Points as a graduation requirement. These points are earned by participating in co-curricular, professional, and advanced activities across three groups. The university does not issue a degree unless students fulfill this requirement.

This web application digitizes the entire workflow — from students uploading certificates to faculty verification and admin oversight — replacing the traditional paper-based process.

04 — Scoring Rules

Key Calculation Rules (KTU 2024)

🏆

Highest Level Only

For the same activity, only the highest achievement level counts. Lower levels are ignored.

🚫

No Double Counting

Participation and Winner points cannot both be claimed for the same event.

📊

Per-Activity Cap

Each activity has a maximum point cap. Points beyond this cap are automatically ignored.

📏

Per-Group Cap

Maximum 40 pts counted per group (30 for Lateral Entry, 20 for PwD). Excess is discarded.

⏱

Programme Period Only

Activities must have been completed during the student's programme duration at KTU.

🎓

Graduation Requirement

Degree will NOT be awarded without fulfilling the Activity Points requirement.

05 — User Roles

Three Types of Users

🎒
Student
B.Tech students across all departments · Login: student1–9 / pass123
  • Upload certificates with activity details, level, date, and file (PDF/JPG/PNG)
  • Track real-time points across Group I, II, and III with progress bars
  • See pending, approved, and rejected certificate statuses
  • View KTU 2024 official activity point guidelines in-app
  • Check eligibility status (whether graduation requirement is met)
  • Download approval PDF after faculty verifies a certificate
👩‍🏫
Faculty Advisor (SFA)
Student Faculty Advisor · Login: faculty1 / pass123
  • View all pending certificates submitted by students
  • Preview uploaded certificate image or PDF directly in the review modal
  • Adjust/override the points awarded before approving or rejecting
  • Add remarks/notes visible to the student
  • Approve → auto-generates and downloads an approval PDF
  • View all students' progress with filters by department, semester, and class division
  • Edit own profile (name, email, designation)
🛡️
Admin
Admin Officer · Login: admin / admin123
  • Manage student and faculty accounts (add, remove, edit users)
  • Add and remove departments from the system
  • Post and delete university circulars (visible to all students)
  • View all students' progress and eligibility across departments
  • Adjust activity point grading rules and overrides
  • Access system-wide analytics and summaries

08 — Technology Stack

Technical Architecture

⚛️

Frontend

React 18 + React Router for SPA routing. Vite as bundler/dev server.

🗄️

Data Layer

Browser localStorage acts as the database. No backend server required.

🎨

Styling

Vanilla CSS with glassmorphism, dark theme, CSS custom properties.

📄

PDF Generation

Custom pdfGenerator.js creates approval certificates on-the-fly in-browser.

🔐

Auth

auth.js handles session management via localStorage. Role-based routing.

📱

Design

Mobile-first, max-width 430px. Bottom navigation bar pattern.

10 — Known Constraints (MVP)

Current Limitations

  • All data is stored in browser localStorage — data is lost if the browser storage is cleared. Not suitable for production without migrating to a real database.
  • Certificate files are stored as base64 strings in localStorage. Large files (>1–2 MB) may exceed the ~5 MB browser storage limit.
  • There is no real authentication — passwords are stored in plain text in localStorage. A real backend with hashed passwords is needed for production.
  • There is only one faculty advisor account. The system does not currently route students to their specific department's advisor.
  • The PDF generation is done client-side in the browser — no server-side PDF rendering.
